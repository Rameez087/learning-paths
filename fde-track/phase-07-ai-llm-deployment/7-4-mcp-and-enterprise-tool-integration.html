7.4 MCP & enterprise tool integration

If you had 10 AI applications and 100 tools, you potentially needed 1,000 different integrations before MCP. Now you need roughly 110.

TL;DR
The Model Context Protocol (MCP), introduced by Anthropic in November 2024, standardizes how AI applications connect to external tools and data sources — "USB-C for AI," one connector that works with any compliant tool rather than custom integration code per tool-per-model combination. By 2026, 28% of Fortune 500 companies have production MCP deployments. For an FDE, MCP is directly relevant to Phase 6's integration patterns: it's often now the standard way an AI agent should connect to a customer's existing systems, rather than a bespoke integration built from scratch.

With 10 AI applications and 100 tools, custom point-to-point integration means potentially 1,000 separate integrations to build and maintain. MCP standardizes the connector interface once, so each tool needs one MCP server and each AI application needs one MCP client — turning a multiplicative problem into roughly an additive one. This is directly the same "consolidation over point connections" principle from 6.1 and 6.5, applied specifically to AI tool integration.

The security reality: adoption has outpaced the security model

The NSA's Artificial Intelligence Security Center published a public Cybersecurity Information Sheet specifically on MCP security in May 2026, with a measured core finding: MCP's adoption has outpaced the development of its security model, leaving organizations exposed to risks the protocol's original designers didn't fully anticipate. Real, documented issues include compromised packages in public registries (a specific CVE compromised 400,000+ developer environments via a shell command injection vulnerability) and MCP servers deployed with missing or poorly configured authentication.

Practical due diligence before connecting an MCP server in a customer environment

  • Verify the source — is this an official vendor-published server, or a community package with unclear provenance?
  • Check for authentication — many early MCP servers were deployed with no auth at all; confirm this one isn't.
  • Watch for tool description changes — a specifically documented attack pattern involves a tool that appears legitimate initially, then changes behavior after gaining trust; alerting on description changes post-installation is a real, recommended defense.
  • Apply least-privilege scoping — connect 7.2's excessive-agency principle directly: an MCP-connected tool should only have the specific access it genuinely needs, not broad standing permissions.

The 2026-07-28 specification update: enterprise-managed identity arrives

A major MCP specification update transitioned the protocol to a stateless core with formal support for enterprise-managed identity and long-running tasks — explicitly aimed at supporting genuinely enterprise-scale, cloud-native deployments rather than the protocol's original single-user, local-first design. This is a specific, current detail worth tracking: the protocol itself is actively evolving in response to exactly the enterprise deployment challenges this track covers.
