12.2 Capstone: Tool-using agent

Phases 4 and 8, built into something that actually reasons, acts, and observes — not just answers.

TL;DR
Build an agent that solves a genuinely multi-step task requiring at least three different tools, using the ReAct loop (8.1) explicitly — with visible, logged reasoning at every step, not just a final answer. The point of this capstone isn't the task itself; it's demonstrating you can design safe, narrow tool contracts (8.2), handle a tool failure gracefully, and stop the loop deliberately rather than letting it run forever or silently give up.

What to build

  • Pick a real, multi-step task: examples include "research a topic across multiple sources and produce a structured summary," "debug a failing test by reading the code, running it, and proposing a fix," or "plan a trip given a budget and constraints, checking real availability."
  • Define at least three narrow, single-purpose tools (8.2) with explicit descriptions, input schemas, and defined failure behavior.
  • Implement the ReAct loop explicitly (8.1) — log every thought, action, and observation, not just the final response.
  • Add an explicit stopping condition tied to actual task completion, not just a fixed step count — and a maximum step limit as a safety net against the infinite-loop failure mode (8.1).
  • Handle at least one tool failure gracefully — a malformed input, a timeout, an empty result — and show the agent recovering or reporting the failure clearly rather than hallucinating past it.

Track your progress

What "done" looks like

A recorded trace (text log is fine) of the agent completing the task end-to-end, showing every thought/action/observation step. A README explaining your tool design choices, why you scoped each tool the way you did (principle of least privilege from 8.2), and a section specifically describing what happens when a tool fails — this is often the most revealing part of an agent project, more than the happy path.

Common places this goes wrong

  • No visible reasoning trace. If you can't show the thought/action/observation steps, you haven't actually demonstrated the ReAct pattern — you've built a single tool-augmented call, not a loop.
  • No stopping condition beyond a step limit. A hard cap prevents infinite loops but doesn't demonstrate the agent knowing when it's actually done — both matter.
  • Tools that are too broad or too many. Recall 8.2 — narrow, unambiguous tools beat a swiss-army-knife tool or an unnecessarily large tool list the agent has to choose among.

This capstone synthesizes Phases 4 (tool calling, async) and 8 (ReAct, tool design, memory) into a single working project.
