6.1 RAG architecture end-to-end

Every piece from Phase 5, assembled into one working pipeline.

TL;DR
Retrieval-Augmented Generation has two distinct phases: an offline indexing phase (chunk documents, embed them, store in a vector index — done once, updated as documents change) and an online query phase (embed the user's question, retrieve the most similar chunks, insert them into the prompt, generate an answer — done on every request). Reported industry data puts around 72% of surveyed enterprises now running RAG in production as of early 2026, up sharply from mostly-pilot status a year prior — the reference architecture has matured enough that planning time has compressed from 6-12 months down to 4-6 weeks.

The full pipeline, concretely

A production RAG system chains together nearly everything from Phases 4-5:

  • Document processing — parsing PDFs, DOCX, HTML into clean text (tools like Apache Tika or Unstructured.io handle this in production).
  • Chunking (5.3) — splitting parsed text into retrievable pieces, with metadata (source, section, page) attached.
  • Embedding (5.1) — converting each chunk into a vector using a dedicated embedding model.
  • Indexing (5.2) — storing vectors in an ANN index (HNSW or IVF), often alongside a keyword index for hybrid search (5.4).
  • Query-time retrieval — embedding the incoming question the same way, searching the index(es), optionally reranking (6.2) the results.
  • Prompt assembly (Phase 3) — inserting the retrieved chunks into the prompt, typically with a system prompt instructing the model to answer only from the provided context.
  • Generation — the LLM call itself (Phase 4), producing an answer grounded in the retrieved material.

Why this beats stuffing everything into context

Recall from 2.5: filling a huge context window costs disproportionately more (quadratic attention cost) and suffers from the "lost in the middle" effect. RAG's entire value proposition is retrieving only the handful of chunks actually relevant to a given query — a few thousand well-chosen tokens usually outperforms a million loosely-related ones, on both cost and answer quality.

Check your understanding

1. What's the key difference between RAG's indexing phase and its query phase?
Indexing is a batch, offline process that prepares the searchable index; querying is the real-time path that runs for every incoming question against that already-built index.
2. Why does RAG typically outperform simply pasting an entire document into a large context window?
This connects directly back to 2.4–2.5: attention cost scales quadratically, and models are measurably less reliable at using information buried deep in a very long context — targeted retrieval sidesteps both problems.
3. What does the system prompt typically instruct the model to do in a RAG pipeline?
Grounding the model's answer in only the retrieved material — rather than letting it freely draw on its general training knowledge — is central to why RAG reduces hallucination on domain-specific questions.
