Azure Learning Roadmap: Start to Advanced

Written 2026-10-07. Facts about services and exams were checked against web search that day; items marked as background knowledge were not.

How to use this roadmap

This roadmap assumes you already know the data engineering corner of Azure well, so it spends its time on the corners you may not: platform fundamentals, infrastructure as code, Databricks, ML and AI, and security. It runs from stage 0 to stage 4, and every stage ends with something you build.

The rule that runs through the whole page: learn every task in at least two ways. Azure usually offers three or four tools for the same job, and choosing between them is the skill employers and exams test. Each domain section below has a table of the options and when to pick each.

Infrastructure as code

Learn Bicep first, then Terraform, and keep both. Microsoft's own guidance recommends Bicep for Azure-only teams and Terraform when you also manage other clouds or services, and Azure Verified Modules supports both.

WayWhat it isStateStrengthLimitPick it when
PortalClick through the UINoneFastest way to explore a serviceNot repeatableLearning and one-off checks
CLI and PowerShellImperative scriptsNoneQuick automation, easy to readYou manage order and idempotency yourselfSmall tasks and glue around other tools
ARM templatesDeclarative JSONNoneThe native format everything compiles toVerbose and hard to readReading old templates; rarely writing new ones
BicepAzure-only language that compiles to ARMStateless; Azure holds the truthDay-one support for new Azure features; simple auth; what-if and deployment stacksAzure only; cannot manage non-Azure services directlyAzure-only teams
TerraformMulti-cloud language (HCL) with a provider modelState file you must store and lockOne tool across clouds and SaaS; mature module ecosystemState to manage; the azurerm provider can lag new featuresMulti-cloud or mixed estates
Terraform with AzAPIMicrosoft's provider that calls the Azure REST API directlySame state fileCovers preview and new features at onceMore verbose than azurermFilling azurerm gaps in a Terraform project

Two details worth knowing. The azurerm provider is co-developed by Microsoft and HashiCorp, while AzAPI is built by Microsoft alone, and the usual pattern is azurerm as the base with AzAPI for anything it lacks. Bicep keeps no state file, so you use what-if to preview a change and deployment stacks to manage resource lifecycle and cleanup.

Order to learn:

  1. Do each task once in the portal and once with the CLI, so you know what the code is describing.
  2. Write the same stack in Bicep: storage account, Key Vault, App Service and a managed identity with role assignments.
  3. Rewrite it in Terraform with azurerm, keeping state in an Azure Storage account.
  4. Replace your hand-written resources with Azure Verified Modules in both tools.
  5. Run both from a pipeline using federated credentials, with no stored secrets.
  6. Break it on purpose: delete a resource by hand and change a setting in the portal, then see how each tool detects and repairs the drift.

Data engineering, modeling and science

The platform choice is the biggest decision here. As of June 2026, Synapse is supported with no announced end-of-life date, but it is in maintenance mode and new investment goes to Fabric. One vendor guide says Databricks is stronger for heavy ML engineering and MLOps, while Fabric fits Microsoft-heavy analytics and BI, and many companies run both. Since your own team is moving a client from Synapse to Databricks, learn all three well enough to explain the trade-offs.

Medallion layers (staging, raw, curated, gold) are a layering pattern, not a modeling style, and they combine with any style above.

For data science, the Azure-specific part is where the work runs: Azure Machine Learning, Databricks notebooks with MLflow, or Fabric Data Science notebooks. The statistics, feature engineering and evaluation underneath are the same everywhere, and your Data Science track covers them.

AI and ML on Azure

Microsoft renamed Azure AI Foundry to Microsoft Foundry on 1 January 2026, and Azure OpenAI is now part of it as "Foundry Models sold by Azure". Expect older tutorials to use the old names for the same things.

How to choose, in short:

  • Use prebuilt AI services when the task is narrow and cost or latency matters, and an LLM when the task needs flexible language handling.
  • Use Azure AI Search when you want managed hybrid retrieval, and pgvector when you want one database for data and vectors. You already built the second, so build the first and compare recall and cost.
  • Treat evaluation as part of the build. Foundry's built-in evaluations and OpenTelemetry-based tracing sit next to the tools you already know.

DP-800 covers the SQL side of this, so the new ground is Foundry, Azure AI Search and Azure Machine Learning.

Certification path

Microsoft retired or replaced most of its Azure developer, data science and AI exams between June and September 2026, so many old study guides point at exams you can no longer take. Retired certifications stay on your transcript, but you cannot sit or renew the exam after its retirement date.

Already retired and not worth studying for: DP-100, AI-102 and AI-900 (June 2026), AZ-204 (31 July 2026) and AZ-500 (31 August 2026). DP-203 was retired earlier, in 2025, per my background knowledge rather than today's search.

A sensible order, based on your gaps and not on any official ladder: AZ-104, then DP-750, then AI-103, then AI-300, then AZ-400 or AZ-305. Each maps to a stage in this roadmap. Before you book any exam, confirm its code and status on its Microsoft Learn credentials page, because this list is changing fast.
