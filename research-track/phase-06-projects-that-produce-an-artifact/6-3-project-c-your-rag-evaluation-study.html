6.3 Project C: your RAG evaluation study

If you have already built a RAG project, turn it into a study with hypotheses, seeds and public data. Same work, scientific framing.

TL;DR
Convert an existing RAG evaluation project into a study: state hypotheses, use public data, run several seeds, include baselines, report intervals and write a preprint draft. The engineering is mostly done. What is added is the discipline from Phase 4. Plan 8 to 12 weeks.

From a project to a study

Project habitStudy habit
Try retrievers until one works wellPre-state which retrievers you will compare and why
Report the best configurationReport all configurations with the same tuning budget
One run, screenshot of a good answerSeveral seeds, intervals, error analysis on failures
Private documentsA public corpus anyone can download
Informal judgement of qualityDefined metrics plus a small human audit

Conversion plan

1. Write the hypotheses

Examples: hybrid retrieval beats dense only on recall at 5 by at least 3 points; reranking helps more on long queries than short ones. Use the claim builder in 4.1.

2. Swap in public data

Choose a public corpus and question set. Keep your private data out of any public result.

3. Add baselines and ablations

BM25 and dense only, then each added component. Give every method the same tuning budget (4.2).

4. Run with seeds and a human audit

Five seeds. Label a random sample of 50 to 100 answers by hand and compare with the automatic metrics.

5. Error analysis

Categorise failures: not retrieved, retrieved but ignored, generated unsupported claims, data defect. A failure taxonomy is a contribution.

6. Write the draft

Use the structure in 7.1 and aim for a workshop paper or preprint.

Venue idea
Workshops on data management for machine learning or on evaluation of language model applications are natural fits. Check each call for scope, deadlines and archival rules (1.3).

Check your understanding

1. What is the key difference between a project and a study?
The study discipline turns working software into checkable evidence.
2. Why add a small human audit?
A hand-labelled sample reveals whether automated scores agree with people.
3. What is valuable in the error analysis?
Categorised failures give readers insight beyond a single number.

Sources: Ragas: Automated Evaluation of Retrieval Augmented Generation; Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks (Lewis et al.); NeurIPS Paper Checklist
