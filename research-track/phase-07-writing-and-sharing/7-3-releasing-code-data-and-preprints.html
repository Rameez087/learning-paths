7.3 Releasing code, data and preprints

Releasing your work is what turns private effort into evidence others can check. It also needs a few decisions about licences, privacy and your employer.

TL;DR
Publish a public repository with a clear README and one command to reproduce your main table, a licence, and documentation for any dataset you create. Post a preprint to make the work citable. Before anything is public, confirm it contains no employer data, code or confidential details, and check dataset licences.

Release checklist

Documents that build trust

Gebru and colleagues propose documenting datasets: why it was created, what it contains, how it was collected, known limitations and recommended uses. A short datasheet in your repo is a courtesy and a credibility signal.

Mitchell and colleagues propose model cards that state intended use, evaluation data and limits. Useful if you release a model.

The most read document. State the claim, show the results, give the single command. A reader should reproduce your main table in under an hour.

Preprints
arXiv lets you post quickly and get a citable record. arXiv requires an endorsement before your first submission and before a new category, so plan ahead. Check each venue's policy on preprints during review before posting.
Protect your employer
Never publish work code, schemas, client names or derived data, and ask before sharing anything built at work. Use public or synthetic data for every public result. When unsure, ask and get the answer in writing.

Safe to publish?

Your repo's git history contains a commit with a company connection string, later deleted.
Deleted files remain in git history. Rotate any exposed secret and publish from a clean history.

Check your understanding

1. What belongs in the first README paragraph?
Readers need to know what you claim and how to check it.
2. Why document a dataset you built?
Datasheets support responsible reuse.
3. What must you check before publishing work related to your job?
Confidentiality obligations apply to code, data and schemas.

Sources: Datasheets for Datasets (Gebru et al.); Model Cards for Model Reporting (Mitchell et al.); arXiv endorsement policy
