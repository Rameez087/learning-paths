4.3 Reproducibility and tracking

A result you cannot rerun next month is not a result. Tracking turns your experiments into something you, and others, can trust.

TL;DR
Record everything needed to rerun an experiment: code version, data version, seeds, hyperparameters, environment and compute. Use an experiment tracker (MLflow or Weights & Biases), pin your dependencies, and keep a config file for each run. If you can rerun it from a clean machine with one command, you are in good shape.

The reproducibility pack

Pineau and colleagues describe the NeurIPS reproducibility effort, which includes a checklist authors fill in covering code, data, hyperparameters and compute. Treat that checklist as a design brief for your own repository, not paperwork to complete at the end.

# minimal seed and tracking pattern (Python)
import random, numpy as np, mlflow

def set_seed(seed: int):
    random.seed(seed)
    np.random.seed(seed)
    # also seed your ML framework here, e.g. torch.manual_seed(seed)

for seed in [0, 1, 2, 3, 4]:
    set_seed(seed)
    with mlflow.start_run():
        mlflow.log_param("seed", seed)
        mlflow.log_param("retriever", "hybrid")
        score = run_experiment()          # your code
        mlflow.log_metric("recall_at_5", score)
Data versioning
Results depend on data as much as code. Tools such as DVC version datasets alongside git, or you can store a dated, hashed snapshot and record its hash in the config. Either way, a future you must be able to tell which data produced which number.

Why did the rerun disagree?

You rerun last month's experiment and get different numbers. You did not pin library versions or record the seed.
Unpinned dependencies and unlogged seeds are the most common causes of unrepeatable runs.

Check your understanding

1. What belongs in a reproducibility pack?
Everything needed to rerun the experiment from scratch must be recorded.
2. Why log the seed for every run?
Seeds let you reproduce a run exactly and quantify run to run variation.
3. Which is the best test of reproducibility?
A clean machine exposes hidden dependencies and manual steps.
