4.4 Data hygiene and leakage

Leakage is the most common way a result looks wonderful and turns out to be wrong. Learning to spot it is one of the most valuable skills in empirical work.

TL;DR
Leakage means information from outside the training data, usually from the test set, influences the model. Split first, before any step that learns from the data (scaling, imputation, feature selection, deduplication). Watch for duplicates across splits, future information in time series and features that encode the label.

Four common leaks

LeakWhat happensFix
Preprocessing before the splitScaler or imputer is fit on all data, so test statistics leak into trainingFit preprocessing on the training set only, inside a pipeline
Duplicates across splitsThe same or near identical record appears in train and testDeduplicate before splitting, or split by group
Temporal leakageThe model sees the future when predicting the pastSplit by time, never randomly, for time dependent data
Target leakageA feature is derived from or only available after the labelReview every feature for when it would exist in production

Kapoor and Narayanan surveyed papers across fields that use machine learning and found leakage widespread, affecting the reliability of many reported results. Your enterprise experience helps here: you already ask when a field is populated and who populates it.

# safe pattern: preprocessing inside a pipeline, split first
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0, stratify=y)
model = make_pipeline(StandardScaler(), LogisticRegression())
model.fit(X_train, y_train)         # scaler sees only training data
print(model.score(X_test, y_test))

Spot the leak

You scale all features using the mean and standard deviation of the full dataset, then split into train and test.
Statistics learned from all data include the test set. Fit the scaler on training data only.
A churn model uses a feature called days_since_cancellation_request. Churn is the label.
The feature would not exist at prediction time for most customers, and it nearly encodes the label.
You predict next month's sales with a random 80/20 split of daily rows over three years.
Time dependent data must be split by time, with training before testing.
The same support ticket text, with trivial edits, appears 400 times, and the random split puts copies in both train and test.
Near duplicates across splits let the model memorise answers. Deduplicate or split by group.

Check your understanding

1. When should you split data relative to preprocessing steps that learn from data?
Fitting on all data lets test information leak into training.
2. Why is a random split wrong for forecasting?
In time dependent problems the test period must come after the training period.
3. Which is an example of target leakage?
If the feature would not be available at prediction time, it should not be used.

Sources: Leakage and the Reproducibility Crisis in ML-based Science (Kapoor, Narayanan); scikit-learn common pitfalls; A Recipe for Training Neural Networks (Karpathy)
