10.1 Train/validation/test splits

Three datasets, three completely different jobs — and using the wrong one for the wrong job silently inflates how good your model looks.

TL;DR
The training set is what the model actually learns from. The validation set is used to tune hyperparameters and make model-selection decisions during development — checked repeatedly. The test set is touched exactly once, at the very end, to estimate how the final model will perform on genuinely unseen data. The cardinal rule: never "peek" at test data while tuning — use the validation set for every decision made during development, or the test set stops being a fair, unbiased estimate of real-world performance.

Why "don't peek at the test set" is the whole point

If you repeatedly check test-set performance while adjusting hyperparameters, you're effectively using the test set to make decisions — which means your final "unbiased" test score is no longer unbiased, since you've implicitly tuned toward it. This is exactly why a separate validation set exists: it absorbs all the repeated checking during development, leaving the test set genuinely untouched until the very end, for one honest, final performance estimate.

Stratified splits: don't let random chance break your split

For classification with imbalanced classes (fraud detection, where positive cases might be 0.1% of all data), a plain random split could — purely by bad luck — put most or all of the rare positive cases into one partition, leaving the model with wildly misleading feedback. A stratified split preserves the same class proportions across train, validation, and test sets, specifically preventing this failure mode.

Time-based splits: when random splitting is actually wrong

For time-series or any data with a temporal structure, a random split can leak future information into training — the model could learn from data that wouldn't have existed yet at prediction time. The correct approach: split by time, training on data up to a cutoff date and testing on data after it, sometimes with a deliberate gap between them to simulate a realistic prediction lead time.

Check your understanding

1. Why should hyperparameter tuning use the validation set rather than the test set?
The test set's value comes specifically from being untouched during development — using it for tuning decisions would contaminate the one honest, final performance check it's meant to provide.
2. Why does a stratified split matter specifically for imbalanced classification problems?
With severe class imbalance, random chance alone can create very unrepresentative splits — stratification directly prevents this by preserving class proportions across all partitions.
3. Why is a random split inappropriate for time-series data?
Temporal data has an inherent ordering that a random split ignores — a time-based split respects that ordering, ensuring the model is only ever evaluated on data that genuinely comes after what it trained on.
