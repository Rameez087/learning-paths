6.3 Deep dive: consistent hashing

Arguably the single most-tested distributed systems concept in real interviews — and it exists to solve exactly the "adding a shard reshuffles everything" problem from 6.2.

TL;DR
Instead of user_id % num_shards, consistent hashing places both shards and data keys onto points around an imaginary circle (a "hash ring"), using a hash function. Each piece of data belongs to the first shard found going clockwise around the ring from its own hash position. Adding or removing a shard only affects the small arc of the ring immediately adjacent to that change — every other shard's data stays exactly where it was, which is the entire point.

Try it: add a shard and watch how little actually moves

Why this is dramatically better than modulo sharding

Recall 6.2's problem: adding one shard to a modulo scheme reshuffles nearly all existing data. On a hash ring, adding a new shard only "steals" the data whose hash falls in the arc between the new shard's position and the next shard clockwise from it — everything else on the ring is completely unaffected. Growing from 8 shards to 9 might move roughly 1/9th of total data, instead of nearly all of it.

Virtual nodes: solving uneven distribution

With only one point per shard on the ring, pure chance can give some shards a much larger arc (and therefore much more data) than others — especially with a small number of shards. Virtual nodes fix this by placing each physical shard at many points around the ring (commonly 100–200 per shard) instead of just one. More points per shard means the law of large numbers evens out the total data each physical shard ends up responsible for, even though any single point's arc is still somewhat random.

Where consistent hashing shows up beyond database sharding

This exact mechanism isn't unique to databases — it's the same idea underneath distributing keys across a cache cluster, routing requests in a CDN, and load balancing in some configurations (recall 3.3's IP hash routing is a simpler cousin of this same family of idea). Recognizing "this is a consistent hashing problem" is one of the single highest-leverage pattern-recognition skills for system design interviews specifically, precisely because it shows up in so many disguises.

This is a genuine refinement addressing a real weakness of the basic single-point-per-shard version — randomness in arc size gets smoothed out by using many points per shard instead of one.
