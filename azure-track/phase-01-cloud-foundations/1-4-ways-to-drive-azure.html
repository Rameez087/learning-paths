1.4 Ways to drive Azure

The same task can be done in the portal, with a command line, in a script, from code or from a template. Knowing all of them is the foundation of this entire track.

TL;DR
Azure offers the portal (clicking), the Azure CLI and PowerShell (commands and scripts), SDKs (from code), REST APIs (what everything uses underneath) and infrastructure as code (Bicep, Terraform). All of them call Azure Resource Manager. Do each task in at least two ways: the portal to learn, the CLI or code to repeat.

The same job, five ways

Everything on this page ends up as calls to Azure Resource Manager.

Create a resource group

Open Resource groups, choose Create, pick subscription, name and region. Quick to explore, but nothing records what you did.

One line, repeatable, easy to paste into documentation.

az group create --name rg-demo --location westeurope --tags project=learning

The same task using the Az module.

New-AzResourceGroup -Name rg-demo -Location westeurope -Tag @{project='learning'}

Declare the group in a template, deployed at subscription scope.

targetScope = 'subscription'

resource rg 'Microsoft.Resources/resourceGroups@2024-03-01' = {
  name: 'rg-demo'
  location: 'westeurope'
  tags: { project: 'learning' }
}

Create it from application code.

from azure.identity import DefaultAzureCredential
from azure.mgmt.resource import ResourceManagementClient

client = ResourceManagementClient(DefaultAzureCredential(), '<subscription-id>')
client.resource_groups.create_or_update('rg-demo', {'location': 'westeurope', 'tags': {'project': 'learning'}})

Azure Cloud Shell gives you a browser based terminal with the CLI and PowerShell preinstalled, which is handy for a first experiment. For daily work, install the Azure CLI locally and sign in with az login.

Which tool fits?

You need to explore a new service for ten minutes to see what it offers.
The portal is the fastest way to explore. Convert the useful parts to code afterwards.
You must create the same environment in dev, test and production, reviewed in pull requests.
Declarative code is repeatable and reviewable.
A one off clean up script for tagged resources across subscriptions.
Quick imperative automation suits small tasks and glue.

Check your understanding

1. What do the portal, CLI, SDKs and IaC tools all call underneath?
Every management tool talks to Resource Manager's API.
2. When is the portal the best choice?
The portal is best for discovery. Repeatable work belongs in code.
3. What is a strength of infrastructure as code?
Code captures the desired state and can be reviewed and rerun.
