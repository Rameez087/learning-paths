9.1 Azure Monitor and KQL

You cannot run what you cannot see. Azure Monitor collects the signals, and KQL is how you ask questions of them.

TL;DR
Azure Monitor gathers metrics (numbers over time), logs (events and records in a Log Analytics workspace) and traces (Application Insights). Resources send logs through diagnostic settings. Query logs with Kusto Query Language (KQL), create alerts and dashboards, and route notifications through action groups.
SignalWhereUse for
MetricsAzure Monitor metrics storeNear real time charts and fast alerts
LogsLog Analytics workspaceInvestigation, rich queries, audits
Traces and requestsApplication InsightsApp performance, dependencies, failures
Activity logSubscription levelWho changed what in Azure

KQL in five lines

AppRequests
| where TimeGenerated > ago(1h)
| where Success == false
| summarize failures = count() by Name, ResultCode
| order by failures desc
| take 10

KQL reads top to bottom: start with a table, then pipe it through where, summarize, project, join and render. Table names differ by data source and configuration, so explore your workspace's schema first.

Mind the bill
Log ingestion is billed by volume. Send only needed logs, use basic or archive tiers for rarely queried data, and set retention deliberately. Cost often surprises teams here.

Which signal?

Alert when CPU stays over 90 percent for 5 minutes.
Metrics suit fast threshold alerts.
Find who deleted a resource last night.
Activity log records control plane operations.
