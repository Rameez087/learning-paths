8.6 Evaluate and observe AI apps

If you cannot measure whether the app is good, every change is a guess.

TL;DR
Build a small evaluation set of real questions with expected answers or criteria. Measure retrieval (did the right chunks come back?) and generation (is the answer grounded, relevant, safe?). Foundry offers evaluators for groundedness, relevance and safety; you can add your own checks. In production, trace each request with OpenTelemetry into Application Insights, and track cost, latency and quality over time.
LayerMeasureExample check
RetrievalRecall at k, precisionIs the gold passage in the top 5?
GenerationGroundedness, relevance, completenessIs every claim supported by retrieved text?
SafetyHarmful content, jailbreak resistanceRed team prompts in the test set
OperationsLatency, tokens, cost, errorsp95 latency and cost per request

Evaluation loop

1. Collect 50 to 200 real cases

Cover common questions and known hard ones. Keep a held out portion.

2. Run the pipeline and score

Use automatic evaluators plus human review of a sample. LLM judges have biases, so calibrate them against humans.

3. Change one thing

Chunk size, prompt, model, reranker. Compare against the previous run.

4. Gate releases

Run the set in CI. Block a release if quality or safety drops.

Research link
Careful evaluation design is the core of the Research Track RAG project. The same discipline makes the production system better.

What to do

Answers sometimes cite facts missing from the retrieved passages.
Ungrounded claims are a measurable defect.
A new model version is available.
Regression testing prevents silent quality loss.
