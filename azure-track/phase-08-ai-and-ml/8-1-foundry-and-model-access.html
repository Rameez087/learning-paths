8.1 Foundry and model access

Azure's AI platform is Microsoft Foundry. It is where you reach models, build agents and run evaluations.

TL;DR
Microsoft Foundry (formerly Azure AI Foundry) is the platform for building AI apps and agents: a catalog of models from several providers, deployment endpoints, an agent service, evaluation, and safety tooling. You create a deployment of a model, get an endpoint, and call it with Entra ID or a key. Plan for quotas, regional availability and model retirement.
Your app talks to a deployment, not to a model name directly.
ConceptWhat to know
DeploymentA named, configured instance of a model with capacity
Deployment typeOptions like standard pay per token, provisioned throughput, and batch. Trade cost against latency guarantees
QuotaPer region and model limits on tokens per minute. Request increases early
Content filtersConfigurable safety filtering on prompts and responses
Model lifecycleModels are retired on published schedules, so pin versions and plan upgrades
# call a deployment with Entra ID (no key)
from openai import AzureOpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

token = get_bearer_token_provider(DefaultAzureCredential(), "https://cognitiveservices.azure.com/.default")
client = AzureOpenAI(azure_endpoint="https://my-resource.openai.azure.com", azure_ad_token_provider=token, api_version="2024-10-21")
r = client.chat.completions.create(model="my-deployment", messages=[{"role": "user", "content": "Hello"}])
print(r.choices[0].message.content)
Verify names and versions
Product names, SDK patterns and API versions change quickly in this area. Treat the sample as a shape, and copy current code from the docs.

Design call

Your app must keep working when a model version is retired.
Retirement dates are published, so plan upgrades.
Avoid storing API keys for model calls.
Identity based access removes keys.
