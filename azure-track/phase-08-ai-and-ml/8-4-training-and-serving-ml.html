8.4 Training and serving ML: Azure ML or Databricks

Two strong platforms cover the model lifecycle. Both support MLflow, so skills transfer.

TL;DR
Azure Machine Learning provides workspaces, compute clusters, pipelines, model registry, managed online endpoints and MLOps integration. Azure Databricks offers notebooks, MLflow tracking and registry in Unity Catalog, Feature Store and model serving next to your data. Both let you track experiments, register models, deploy endpoints and automate retraining.

The lifecycle

1. Data and features

Versioned datasets and reusable features. Avoid leakage (Research Track 4.4).

2. Train and track

Log parameters, metrics and artifacts with MLflow. Compare runs, not memories.

3. Register and approve

Store the model with lineage to code and data. Promote through stages with checks.

4. Deploy

Real time endpoint or batch scoring. Use blue green rollout and autoscaling.

5. Monitor and retrain

Watch data drift, performance and cost. Trigger retraining on evidence.

Infrastructure for ML
Training needs compute quotas, GPUs in specific regions, private networking to data and managed identities for access. Plan these early with the networking and security phases.
