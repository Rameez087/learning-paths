2.1 Virtual machines and scale sets

A VM is the most flexible compute option and the one that asks the most of you. Use it when you need control, and use something higher level when you do not.

TL;DR
A virtual machine gives you an operating system you manage (patching, scaling, security). Choose a size family for the workload, use managed disks, spread across availability zones for resilience, and use scale sets to run many identical VMs that scale automatically. Pricing options include pay as you go, reservations, savings plans and spot.

What you choose when you create a VM

From one VM to a scale set

1. One VM

Simple and fast to start. A single point of failure and you resize by hand.

2. Zones and a load balancer

Two or more VMs across zones behind a load balancer. One failing does not stop the service.

3. Virtual machine scale set

Identical VMs managed as one group. Autoscale rules add and remove instances based on metrics or a schedule.

4. Move up the stack

If you are only running a web app, App Service or Container Apps removes patching and scaling from your plate (2.2, 2.4).

Responsibility
With a VM you own the operating system, patches, antivirus, backups and most security configuration. Platform services take much of that off you. Reach for a VM when you need a specific OS, custom software, legacy applications or full control.

VM or something else?

You need to run a legacy Windows application that requires a specific installed driver.
Custom OS level requirements are the classic case for VMs.
You run a stateless web API and do not want to patch servers.
Platform services remove operating system management.
A batch job can be interrupted and restarted, and you want the lowest cost.
Spot capacity is cheap but can be evicted, so it suits interruptible work.

Check your understanding

1. What does a virtual machine scale set do?
Scale sets handle instance count and scaling rules for identical VMs.
2. Who patches the operating system on a standard Azure VM?
IaaS means the customer manages the OS.

Commitments reduce cost when usage is predictable.
