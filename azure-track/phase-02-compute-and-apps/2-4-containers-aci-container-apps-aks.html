2.4 Containers: ACI, Container Apps and AKS

Azure has several ways to run containers. The choice is how much of the platform you want to manage.

TL;DR
Azure Container Instances runs a single container quickly. Container Apps runs containerised apps and jobs on a managed platform built on Kubernetes, with autoscaling (including to zero) and no cluster to manage. AKS is managed Kubernetes where you control the cluster. Start with the simplest that meets your needs.

The spectrum

More control means more to operate. Most web workloads fit the middle option.

Choose by questions

1. Is it a single short lived container?

Yes: ACI, or a Container Apps job. No: continue.

2. Is it a web app, API or background worker with scaling needs?

Yes: Container Apps. It handles ingress, revisions and event driven scaling with KEDA.

3. Do you need Kubernetes APIs, custom operators or a team that already runs Kubernetes?

Yes: AKS. Budget for upgrades, networking, node pools and security.

# deploy a container app (CLI)
az containerapp env create -g rg-demo -n env-demo -l westeurope
az containerapp create -g rg-demo -n api-demo --environment env-demo \
  --image mcr.microsoft.com/k8se/quickstart:latest --target-port 80 --ingress external \
  --min-replicas 0 --max-replicas 5

Pick one

A team of three wants to run a containerised API that scales with queue length and sometimes idles overnight.
Container Apps offers event driven scaling including to zero without a cluster to manage.
A platform team needs custom CNI plugins, admission controllers and strict node level control.
Deep Kubernetes control is what AKS provides.

Check your understanding

1. Which option needs no Kubernetes cluster to manage and can scale to zero?
Container Apps abstracts the cluster and supports scale to zero.
2. When is AKS the right choice?
AKS gives control at the cost of operational effort.
3. What drives event based scaling in Container Apps?
Container Apps uses KEDA for event driven autoscaling.
