6.2 Bicep in practice: modules, what-if and deployment stacks

Real infrastructure is many files, previewed before applying, and cleaned up on purpose.

TL;DR
Modules package reusable Bicep and can be shared through a registry. What-if previews changes before you deploy. Deployment stacks manage a set of resources as one unit, can protect them from changes outside the stack (deny settings), and can delete resources that you remove from the template. Bicep keeps no state file; Azure itself is the source of truth.

Modules

module storage 'modules/storage.bicep' = {
  name: 'storageDeploy'
  params: {
    env: env
    location: location
  }
}

// or from a private registry
module net 'br:myregistry.azurecr.io/bicep/network:v1' = {
  name: 'netDeploy'
  params: { addressSpace: '10.20.0.0/16' }
}

Preview, then apply

What-if output shows create, modify, delete and ignore per resource. Read it before you deploy.

What-if is best effort: some properties produce noise, and not every change is predicted perfectly. Treat it as strong guidance, not a guarantee.

Deployment stacks

A plain deployment never deletes things you removed from the file (incremental mode). A stack tracks the resources it created and can detach or delete them when they leave the template, and can apply deny settings so people cannot edit managed resources by hand. This answers the old question of how to clean up in Bicep without a state file.

az stack group create --name stack-demo --resource-group rg-demo \
  --template-file main.bicep \
  --action-on-unmanage deleteResources \
  --deny-settings-mode denyDelete
Check stack availability
Deployment stacks have been maturing. Confirm the current support level, scopes and deny settings behaviour in the docs before relying on them in production.

Which tool step?

You want to see what a template change would do before applying it.
What-if previews without changing anything.
You removed a resource from the template and want it deleted in Azure too.
Incremental deployments leave removed resources in place.

Check your understanding

1. What does what-if do?
It is a dry run.
2. Does Bicep keep a state file?
Bicep is stateless.
3. Why use deployment stacks?
Stacks can delete unmanaged resources and block outside edits.
