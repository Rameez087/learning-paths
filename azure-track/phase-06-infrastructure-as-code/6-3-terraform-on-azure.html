6.3 Terraform on Azure

Terraform is multi cloud and keeps state. On Azure you mainly use the azurerm provider, with AzAPI for the newest features.

TL;DR
Terraform uses HashiCorp Configuration Language and a state file that maps your code to real resources. The workflow is init, plan, apply. State must live in a shared, locked, protected place such as an Azure Storage container. The azurerm provider covers most services with friendly resource types. The AzAPI provider talks to any ARM API version directly, so new features are available immediately. 
terraform {
  required_providers {
    azurerm = { source = "hashicorp/azurerm", version = "~> 4.0" }
  }
  backend "azurerm" {
    resource_group_name  = "rg-tfstate"
    storage_account_name = "sttfstate12345"
    container_name       = "tfstate"
    key                  = "dev.tfstate"
  }
}
provider "azurerm" {
  features {}
  subscription_id = var.subscription_id
}

resource "azurerm_storage_account" "sa" {
  name                            = "st${var.env}${random_string.s.result}"
  resource_group_name             = var.rg
  location                        = var.location
  account_tier                    = "Standard"
  account_replication_type        = "LRS"
  is_hns_enabled                  = true
  allow_nested_items_to_be_public = false
  min_tls_version                 = "TLS1_2"
}
The plan compares code, state and real infrastructure.

State is the thing to protect

  • Store it remotely (an Azure Storage container) so teams share one copy, with locking via blob leases.
  • Restrict access: state can contain sensitive values.
  • Never edit it by hand. Use terraform state commands for moves and imports.
  • Split state by blast radius and lifecycle, such as networking apart from applications.
Drift
If someone changes a resource in the portal, Terraform notices at the next plan and proposes to revert it. Bicep what-if shows similar differences, but there is no state to reconcile.

Terraform situation

Your team already manages AWS and Azure with one tool and review process.
Terraform works across clouds with one workflow.
A new Azure service just launched and azurerm does not support it yet.
AzAPI uses the ARM API directly, so it covers new resources.

Check your understanding

1. What does Terraform state do?
It is how Terraform knows what it manages.
2. Where should team state live?
Shared state needs locking and protection.
3. What is AzAPI for?
It bypasses the lag of friendly resource types.
