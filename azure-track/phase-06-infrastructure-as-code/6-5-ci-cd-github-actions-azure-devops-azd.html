6.5 CI/CD: GitHub Actions, Azure DevOps and azd

Infrastructure belongs in a pipeline: reviewed, previewed, and applied with an identity that has no stored secret.

TL;DR
Treat infrastructure like code: pull request, automated checks, preview, approval, apply. Sign in with OIDC federation rather than a stored secret. GitHub Actions and Azure Pipelines both do this. The Azure Developer CLI (azd) bundles infrastructure and app deployment for a project template.

A minimal workflow

name: deploy
on:
  push:
    branches: [main]
permissions:
  id-token: write   # needed for OIDC
  contents: read
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: prod
    steps:
      - uses: actions/checkout@v4
      - uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}
      - name: What-if
        run: az deployment group what-if -g rg-app -f infra/main.bicep
      - name: Deploy
        run: az deployment group create -g rg-app -f infra/main.bicep
Previews run on every pull request, deployment needs an approval for production.
  • Use separate identities and federated credentials per environment, each with only the roles it needs.
  • Protect the production environment with required reviewers.
  • Keep Terraform state access limited to the pipeline identity.
  • Run policy checks and linters before the preview step.

Which pipeline system

Code and pipeline in one place. Federated credentials trust a repository, branch or environment.

Part of Azure DevOps. Service connections can use workload identity federation instead of secrets.

A developer focused CLI. azd up provisions infrastructure from Bicep or Terraform and deploys the app. Useful for templates and demos, and it can generate a pipeline.

Never commit credentials
If a client secret ever reaches a repository, rotate it immediately. Federation removes the secret altogether, so prefer it.

Pipeline choice

Pipeline needs to deploy to Azure with no stored secret.
Federation issues short lived tokens.
A new developer wants to stand up a sample app and its infrastructure in one command.
azd bundles provisioning and deployment.
