5.1 Managed identities and workload identity federation

The best secret is the one that does not exist. Let Azure and your pipelines prove who they are without passwords.

TL;DR
A managed identity is an identity Azure creates and rotates for a resource, so code can get tokens without any stored credential. System assigned identities live and die with the resource, user assigned identities are standalone and reusable. For pipelines outside Azure, workload identity federation lets GitHub Actions or Kubernetes exchange their own token for an Azure token, with no secret stored.

How a managed identity works

No password, key or certificate is stored in code or settings.
TypeLifecycleUse when
System assignedTied to one resource, deleted with itOne resource needs its own identity
User assignedCreated separately, attached to many resourcesSeveral resources share access, or you need the identity before the resource exists
// Python: same code works locally (your login) and in Azure (managed identity)
from azure.identity import DefaultAzureCredential
from azure.storage.blob import BlobServiceClient

cred = DefaultAzureCredential()
svc = BlobServiceClient("https://mystore.blob.core.windows.net", credential=cred)
for c in svc.list_containers():
    print(c.name)
Grant the role
A managed identity has no access until you give it an RBAC role at the right scope, for example Storage Blob Data Reader on one storage account. The identity existing is not the same as it being allowed.

Federation for pipelines

Instead of storing a service principal secret in GitHub, you create a federated credential on an app registration or user assigned identity that trusts tokens from a specific repository and branch or environment. The pipeline signs in with OIDC and receives a short lived Azure token. Section 6.5 shows the workflow.

Pick the mechanism

A Function App needs to read secrets from Key Vault.
Managed identities remove stored credentials.
GitHub Actions must deploy to Azure without storing a client secret.
Federation exchanges the GitHub token for an Azure token.

Check your understanding

1. What is the main benefit of a managed identity?
Azure manages the credential lifecycle.
2. When pick user assigned over system assigned?
User assigned identities are reusable and independent.
3. What does workload identity federation replace?
The external system proves identity with its own token.
