5.2 Key Vault and App Configuration

Secrets, keys and settings each have a proper home. Keep them out of code and out of source control.

TL;DR
Azure Key Vault stores secrets, keys and certificates with access control and audit logs. Use the RBAC permission model, soft delete and purge protection. Azure App Configuration holds non secret settings and feature flags, and can reference Key Vault secrets. Apps read both with a managed identity.
StoreHoldsNotes
Key Vault secretsPasswords, connection strings, API keysVersioned, with expiry and rotation support
Key Vault keysEncryption keys, optionally HSM backedOperations happen in the vault so the key never leaves
Key Vault certificatesTLS certificates with lifecycle managementCan auto renew with supported issuers
App ConfigurationSettings and feature flagsNot for secrets, but supports Key Vault references

Good practice

  • Use one vault per application and environment, so access is narrow and blast radius is small.
  • Use RBAC roles such as Key Vault Secrets User instead of legacy access policies for new vaults.
  • Enable soft delete and purge protection so deletions are recoverable.
  • Restrict network access and use private endpoints for sensitive vaults.
  • Prefer not to need a secret at all: managed identity to the target service beats a stored password.
# Bicep: a vault with RBAC and protection
resource kv 'Microsoft.KeyVault/vaults@2023-07-01' = {
  name: 'kv-${uniqueString(resourceGroup().id)}'
  location: resourceGroup().location
  properties: {
    sku: { family: 'A', name: 'standard' }
    tenantId: subscription().tenantId
    enableRbacAuthorization: true
    enableSoftDelete: true
    enablePurgeProtection: true
  }
}
API versions
The API version in the sample may be older than the newest. Check the template reference for current versions when you write real templates.

Where does it go?

A third party API key.
Secrets belong in a vault with access control and audit.
A feature flag that turns on a new page for 10 percent of users.
Feature management is a built in App Configuration capability.

Check your understanding

1. What does purge protection do?
Deleted vaults and objects stay recoverable.
2. Where should feature flags live?
It supports feature management.
3. Preferred permission model for new vaults?
RBAC is consistent with the rest of Azure.
