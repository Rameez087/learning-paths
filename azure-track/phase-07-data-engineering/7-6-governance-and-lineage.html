7.6 Governance and lineage: Purview, Unity Catalog and OpenLineage

If nobody can find a dataset, trust it, or tell who is allowed to use it, the platform fails regardless of speed.

TL;DR
Governance covers a catalog (what exists), classification (what is sensitive), access control, quality and lineage (where data came from and what depends on it). Microsoft Purview catalogs and classifies data across sources. Unity Catalog governs Databricks assets with lineage built in. OpenLineage is an open standard for emitting lineage events from tools like Spark and Airflow, so lineage is not locked to one vendor.
ToolDoesBest fit
PurviewCatalog, scanning, classification, data map across many sourcesEstate wide discovery and policy
Unity CatalogAccess control, lineage and audit for lakehouse tables, volumes and modelsDatabricks centred platforms
OpenLineageOpen event format for run level lineageMixed tools, avoiding lock in

What good governance looks like in practice

  • Every dataset has an owner, a description and a sensitivity label.
  • Access is granted to groups through the catalog, not to individuals on storage.
  • Lineage lets you answer: if this source column changes, what breaks?
  • Quality checks run in the pipeline and failures are visible, not silent.
