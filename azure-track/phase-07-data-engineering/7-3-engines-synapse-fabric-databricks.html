7.3 Engines: Synapse, Fabric and Databricks

Three platforms dominate Azure analytics. Know what each is for, and what has changed.

TL;DR
Azure Databricks is an Apache Spark based lakehouse platform with Delta Lake, Unity Catalog and strong ML tooling. Microsoft Fabric is a SaaS analytics platform with OneLake, Spark, warehouse, real time and Power BI together. Azure Synapse Analytics is the earlier integrated service; Microsoft has described it as in maintenance mode, so new projects usually choose Fabric or Databricks. Verify the current status before designing.

Product roadmaps move quickly. Read the current Microsoft and Databricks documentation, and ask for the current migration guidance, before choosing for a long lived system.

A decision path

Pick an engine

1. Is Power BI the main consumer and the team small?

Fabric reduces moving parts, since lakehouse, warehouse and semantic models share OneLake.

2. Is heavy Spark engineering or ML central, or is multi cloud a goal?

Databricks has the deeper engineering and ML toolset and works with open formats.

3. Do you already run Synapse?

Plan a migration path rather than a rewrite, and check current guidance for dedicated SQL pools.

4. Can you use both?

Many organisations do: Databricks for engineering, Fabric or Power BI for consumption, sharing Delta data through shortcuts or mirrored access.

Choose

A small team wants lakehouse, warehouse and dashboards with minimal setup.
Fabric is the integrated SaaS option.
A data engineering team builds Spark pipelines and ML models, wants Unity Catalog and open Delta tables.
Databricks is built for this.

Check your understanding

1. What is OneLake?
It stores Fabric data in Delta format.
2. What is Synapse's described status?
New projects generally choose Fabric or Databricks, but verify current guidance.
3. What is Unity Catalog?
It centralises access control and lineage.
