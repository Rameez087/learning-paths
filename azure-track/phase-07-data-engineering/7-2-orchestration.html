7.2 Orchestration: Data Factory, Synapse, Fabric and workflows

Something has to run your pipelines in order, retry them and tell you when they fail.

TL;DR
Azure Data Factory orchestrates and moves data with pipelines, activities and triggers, using the Copy activity and mapping data flows. Synapse pipelines and Fabric Data Factory offer similar capabilities inside their platforms. Databricks Workflows orchestrate notebooks and jobs near the compute. Open source tools such as Airflow can run on Azure too. Choose based on where your compute lives and your team's skills.
OrchestratorStrengthConsider when
Data FactoryMature, 100+ connectors, copy at scale, scheduling and triggersMoving data between many systems; orchestrating other engines
Synapse pipelinesSame engine as ADF inside SynapseYou already work in a Synapse workspace
Fabric Data FactoryPipelines integrated with OneLake and Fabric itemsYour platform is Fabric
Databricks WorkflowsJobs, tasks and dependencies beside the notebooks and Delta tablesYour logic is mostly in Databricks
Airflow or similarCode defined DAGs, large ecosystemComplex dependencies, existing Airflow skills

Concepts that transfer

  • Idempotency: a rerun must not duplicate data. Use merge or overwrite by partition.
  • Retries and alerts: expect transient failures, alert on persistent ones.
  • Parameters: one pipeline for many tables, driven by a metadata table.
  • Triggers: schedule, tumbling window, storage event.
  • Dependencies and backfills: design so you can reprocess a date range safely.
Check product direction
Microsoft's data platform is evolving, with Fabric receiving much of the investment. Read the current guidance on which products fit new projects before committing.

Pick the orchestrator

Copy tables nightly from five different databases into a lake.
Copy at scale with built in connectors is its main job.
Your whole stack is Databricks and you need task dependencies between notebooks.
Orchestration beside the compute is simplest.

Check your understanding

1. What does idempotent mean for a pipeline?
Safe reruns make recovery easy.
2. Which has 100+ built in connectors for moving data?
Connectors and copy are its strength.
3. Why parameterise pipelines?
Metadata driven design reduces duplication.
