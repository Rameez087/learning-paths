7.5 Streaming: Event Hubs, Stream Analytics, Spark and Fabric real time

Some data cannot wait for a nightly batch. Streaming is a separate way of thinking, with its own failure modes.

TL;DR
Event Hubs ingests millions of events per second and has a Kafka compatible endpoint. Stream Analytics runs SQL like queries over streams. Spark Structured Streaming (Databricks or Fabric) processes streams with the same APIs as batch. Fabric Real-Time Intelligence adds eventstreams and a KQL based store. Key ideas: event time versus processing time, windows, watermarks and exactly-once versus at-least-once delivery.
The log decouples producers from consumers and lets you replay.
IdeaMeaning
Event timeWhen the event happened. Use it for correct answers
Processing timeWhen your system saw it. Easy but wrong when data arrives late
WindowA bounded slice of the stream: tumbling, hopping, sliding, session
WatermarkHow long to wait for late events before closing a window
At-least-onceDuplicates possible, so consumers must be idempotent
Do you need streaming at all?
Streaming costs more to build and operate. If a five minute micro batch meets the business need, it is often simpler. Ask what decision changes if data arrives in seconds.

Choose

Ingest telemetry from thousands of devices and replay it later for new consumers.
A partitioned, retained log supports many consumers and replay.
Simple tumbling window counts per minute written to Power BI, SQL skills only.
Stream Analytics offers a SQL query language over streams.

Check your understanding

1. Why prefer event time over processing time?
Late data is normal.
2. What is a watermark?
It lets windows close.
3. What follows from at-least-once delivery?
Duplicates must be harmless.
