7.4 Data modeling: facts, dimensions and slowly changing data

A model that matches how people ask questions is worth more than a clever pipeline.

TL;DR
A star schema has fact tables (measurable events such as orders) surrounded by dimension tables (descriptive context such as customer, product, date). Fix the grain of a fact first: what one row means. When a dimension attribute changes, a slowly changing dimension strategy decides whether history is kept: type 1 overwrites, type 2 adds a new versioned row.

Try it: type 1 versus type 2

A customer moves city several times. Press the button and watch how each approach stores it.

Type 1: overwrite

Type 2: keep history

With type 1 you can only answer questions about where the customer lives now. With type 2 a fact row joins to the dimension version that was valid when the order happened, so last year's sales stay attributed to last year's city.

Facts hold numbers and keys. Dimensions hold descriptions.
DecisionGuidance
GrainWrite it as a sentence: one row per order line. Everything in the table must fit that grain
KeysUse surrogate keys in dimensions so you can version rows
Type 1Corrections, or attributes where history does not matter
Type 2Attributes where history changes the answers, such as region or segment
DatesUse a date dimension, not raw timestamps, for calendar logic
Do not model everything as one wide table
Wide tables are fine as a gold layer product for one purpose, but a conformed set of dimensions lets many facts share definitions and keeps numbers consistent across reports.

Which SCD type?

A typo in a customer name is corrected.
Corrections should not create fake history.
Sales reports by customer region must not change when the customer later moves.
History must be preserved to keep past results stable.

Check your understanding

1. What is the grain of a fact table?
Fixing the grain first prevents ambiguous measures.
2. What does SCD type 2 do?
Validity dates distinguish the versions.
3. Why surrogate keys in dimensions?
The business key repeats across versions.
