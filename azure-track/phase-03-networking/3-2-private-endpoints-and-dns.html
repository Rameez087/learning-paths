3.2 Private endpoints and DNS

Most Azure services have a public address by default. Private endpoints bring them into your network, and DNS is the part that goes wrong.

TL;DR
A private endpoint gives a PaaS resource (storage, SQL, Key Vault and more) a private IP address inside your subnet, using Azure Private Link. Traffic stays on the Microsoft network and you can turn off public access. The catch is DNS: the service name must resolve to the private IP from inside your network, normally through a private DNS zone linked to the VNet.

What changes

Without the DNS step the name still resolves to the public address and the connection fails once public access is off.
OptionWhat it doesNote
Service endpointKeeps a subnet's traffic to a service on the Azure backbone, still to the public IPSimpler, older, less isolation
Private endpointA private IP in your subnet for one resourceWorks from on premises too, needs DNS
Public access restricted by IPFirewall allow list on the serviceEasiest, still a public address

Setting one up

1. Create the endpoint

Pick the resource and the sub resource (for storage, blob or dfs) and the subnet. It gets a network interface with a private IP.

2. Create or reuse a private DNS zone

Each service type has a standard zone name, such as privatelink.blob.core.windows.net. The docs list them.

3. Link the zone to your VNets

Every network that must resolve the private address needs a link. Hub and spoke designs often centralise zones in the hub.

4. Handle on premises resolution

On premises DNS must forward those names to Azure, for example through Azure DNS Private Resolver.

5. Disable public network access

Only after testing. Check every client, including build agents and data tools.

Most common failure
A private endpoint exists but the name still resolves publicly. Run nslookup from the client and check it returns the private IP before debugging anything else.

Which fits?

A database must never be reachable from the internet and on premises tools must also reach it.
Private endpoints work across connected networks, but DNS must resolve them.
A quick dev setup where a single office IP needs to reach storage.
For low risk dev work an IP allow list is enough, though weaker.

Check your understanding

1. What is the usual cause of a private endpoint not working?
Name resolution must return the private IP.
2. What does a private endpoint give a resource?
It maps the service into your network via Private Link.
3. What helps on premises clients resolve private zones?
On premises DNS must forward the private link names to Azure.
