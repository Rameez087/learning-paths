3.4 Load balancing options

Azure has four load balancing services. Two questions pick the right one: is it HTTP, and is it regional or global?

TL;DR
Azure Load Balancer is layer 4 (TCP and UDP), regional. Application Gateway is layer 7 (HTTP) with WAF, regional. Front Door is layer 7 and global, with CDN and WAF at the edge. Traffic Manager is DNS based routing across regions for any protocol.

Two axes

RegionalGlobal
HTTP and HTTPS (layer 7)Application GatewayFront Door
Any protocol (layer 4 or DNS)Load BalancerTraffic Manager (DNS)

Each one

High throughput, low latency TCP and UDP distribution inside a region. Public or internal. Health probes decide which backends receive traffic. No understanding of HTTP paths.

Understands HTTP: URL path routing, host headers, TLS termination, cookie affinity, and an optional web application firewall. Regional, and sits inside a VNet.

Global entry point at Microsoft edge locations. Accelerates and routes HTTP traffic to the nearest healthy origin, with caching and WAF.

Returns a DNS answer based on health and routing method (priority, performance, geographic). Clients then connect directly, so there is no inline proxy and no HTTP features.

They combine
A common pattern is Front Door in front for global routing and WAF, with Application Gateway or an internal load balancer per region behind it. Do not add layers you do not need.

Pick one

Distribute a TCP database protocol across VMs in one region.
Layer 4 distribution inside a region is Load Balancer's job.
A web app in two regions needs global routing, caching and a WAF.
Front Door is the global layer 7 service with WAF and caching.
Route /api to one pool and /images to another in a single region.
Path based routing is layer 7.

Check your understanding

1. Which service works at layer 4?
Load Balancer handles TCP and UDP.
2. Which is a global HTTP entry point with edge caching?
Front Door runs at Microsoft edge locations.
3. How does Traffic Manager route?
Clients connect directly after the DNS answer.
