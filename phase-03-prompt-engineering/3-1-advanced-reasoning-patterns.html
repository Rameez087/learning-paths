3.1 Advanced reasoning patterns

Self-consistency and Tree of Thoughts — real accuracy gains, real cost, and where the line between them sits.

TL;DR
Self-consistency runs the same chain-of-thought prompt several times and takes the majority answer — cheap, and it closes most of the accuracy gap on math and reasoning tasks. Tree of Thoughts (ToT) goes further: it branches at each reasoning step, evaluates each branch, and prunes the weak ones — far more powerful on genuinely hard search problems, and far more expensive. The 2026 rule of thumb from practitioners: reach for self-consistency first; only escalate to full ToT when self-consistency demonstrably isn't enough, because most of the time it is.

Try it: self-consistency in action

Below is a real failure case, drawn from the paper that introduced this technique: a single greedy chain-of-thought pass gets this arithmetic problem wrong. Run it several times with independent reasoning paths and take the majority vote instead.

Q: When I was 6, my sister was half my age. Now I'm 70. How old is my sister?

(Correct answer: 67 — the age gap is fixed at 3 years, not a ratio.)

On the exact benchmarks reported in the original paper, self-consistency lifted accuracy by +17.9 points on GSM8K (grade-school math) and +12.2 points on AQuA (algebra word problems), just by sampling multiple paths and voting — no fine-tuning, no extra training, no evaluator model required.

Tree of Thoughts: search instead of voting

Self-consistency samples several complete reasoning paths independently and votes at the end. Tree of Thoughts is a different structure entirely: at each individual step, the model generates several possible next moves, an evaluator scores them, and the weak branches get pruned before continuing — genuine search through a tree of partial solutions, not parallel full attempts.

On the "Game of 24" puzzle (combine four numbers with arithmetic to reach 24) from the paper that introduced ToT, a single chain-of-thought prompt solved it 4% of the time. Wrapped in Tree of Thoughts — branching at each numeric step, pruning under a value prompt — the same underlying model solved it 74% of the time.

When each technique is overkill

  • Self-consistency is overkill for general content generation, casual Q&A, or anything where a single wrong answer is low-stakes and cheap to correct. It earns its cost when a wrong answer is significantly more expensive than a few extra inference calls — financial calculations, legal analysis, medical-adjacent reasoning support.
  • Tree of Thoughts is overkill for anything self-consistency already handles well. Its deliberate branching search is expensive per call, so it's reserved for problems requiring genuine multi-step exploration with clear intermediate states to evaluate — puzzle-like search problems, not everyday reasoning tasks.
  • A cheaper alternative to both, when it applies: replace an LLM-based evaluator with a deterministic checker whenever the task allows one — schema validation, arithmetic verification, unit tests, regex matching. This keeps search quality high while cutting per-step cost substantially.

Check your understanding

1. How does self-consistency decide on a final answer?
Self-consistency replaces greedy single-path decoding with multiple independent samples, then a simple majority vote across the final answers — no separate evaluator model required.
2. What's the key structural difference between Tree of Thoughts and self-consistency?
Self-consistency's paths never interact until the final vote; ToT actively prunes weak branches mid-reasoning using an evaluator, making it more powerful on search-like problems but considerably more expensive.
3. When should you replace an LLM-based evaluator with a deterministic checker in a ToT-style pipeline?
A deterministic checker is both cheaper and more reliable than an LLM judge whenever the correctness criterion can be checked mechanically — this is a straightforward cost and quality win wherever it's available.
