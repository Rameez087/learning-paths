8.1 The ReAct loop

The pattern that makes an AI stop and check something instead of confidently guessing.

TL;DR
ReAct (Reasoning + Acting) interleaves explicit reasoning with tool calls in a repeating loop: the model writes a thought (what should I do next, and why), takes an action (calls a tool — this is 4.2's tool use, now driving a loop instead of a single call), reads the observation (the tool's result), and reasons again from there. This repeats until the model decides it has enough to answer. The original paper demonstrated concrete gains from this structure: a 34% improvement on the ALFWorld benchmark and 10% on WebShop versus reasoning-only or action-only approaches.

Try it: step through a real ReAct loop

Task: "What's the current weather in the city where the 2028 Olympics will be held?"

Why interleaving beats reasoning-then-acting or acting-only

A model that only reasons (no tools) can only guess — it might not know, or might confidently state something wrong. A model that only acts, without explicit reasoning between steps, can't explain why a tool result changed its plan, making failures hard to diagnose. Interleaving both means each action is grounded in an explicit, inspectable thought, and each subsequent thought is grounded in real, freshly-observed information rather than an assumption made before any tool was called.

The five-stage view: perceive, reason, plan, act, observe

A slightly more granular description of the same underlying loop breaks it into five repeating stages: the agent perceives new input (a user message, a tool result, an error), reasons about what it means, plans what to do about it, acts by calling a tool, and observes the result — which becomes the next perception, closing the loop.

Real failure modes worth knowing before you build one

  • Infinite loops — with no clear objective-verification step, an agent can keep "refining" indefinitely because it can always find something to improve. This is a documented, real production failure pattern, not a hypothetical.
  • Goal drift — the agent pursues a related but subtly different goal than the one asked for, often triggered by an ambiguous task spec or a tool result that pulls reasoning sideways.
  • Context overflow — long-running loops accumulate observations until they fill the context window (2.5), and reasoning quality degrades as a result. Summarizing or compressing earlier steps is the standard mitigation.
  • Silent failures — the agent produces confident-sounding final output while having made no real progress; tool calls happened, but didn't actually accomplish the task. This is why evaluation (Phase 9) matters as much for agents as for any other LLM system.

Check your understanding

1. What does the "observation" step in a ReAct loop consist of?
Observation is specifically the real-world result of the action just taken — it's what feeds the next round of reasoning with fresh, grounded information rather than an assumption.
2. Why does interleaving reasoning and acting outperform pure reasoning-only responses on tasks requiring outside information?
The reported 34%/10% benchmark gains specifically come from grounding the reasoning in real observed results rather than the model's unverified internal assumptions.
3. What causes the "infinite loop" failure mode in agent systems?
Without an explicit stopping condition tied to actual task completion, an agent has no structural reason to stop — it can keep refining indefinitely, which is a documented real production incident pattern, not a rare edge case.

Sources: Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models" (NeurIPS/ICLR, 2022); Oracle "What Is the AI Agent Loop?" (2026); DataScienceDojo "Agentic loops explained" (2026).
