6.4 Evaluating retrieval quality

A great faithfulness score can hide a broken retriever. You need both halves measured.

TL;DR
RAG has two failure surfaces — retrieval and generation — and a single aggregate score can mask which one is actually broken. The four canonical metrics (from the widely-used RAGAS framework): context precision and context recall measure the retriever (is what's retrieved relevant? is everything needed actually retrieved?); faithfulness and answer relevancy measure the generator (is the answer grounded in the retrieved context? does it address the question?). A system can score high on generation metrics while its retriever is quietly failing — you need to measure both halves separately to know which one to fix.

The four metrics, precisely

  • Context precision — of everything retrieved, how much is actually relevant? Low precision means the retriever is pulling in noise alongside the useful chunks, diluting what the generator sees.
  • Context recall — of everything needed to fully answer the question, how much was actually retrieved? Low recall means information is missing entirely, regardless of how clean the retrieved chunks are.
  • Faithfulness — of the claims in the generated answer, how many are actually supported by the retrieved context? Low faithfulness means the model is adding unsupported claims — hallucinating, even with correct context in front of it.
  • Answer relevancy — does the generated answer actually address the question asked? A technically faithful answer can still be relevancy-low if it goes off-topic or answers a related-but-different question.

Why this decomposition matters more than one aggregate number

A documented real-world failure pattern: a legal research RAG system scores 0.91 on faithfulness in its offline evaluation set — looking excellent. Weeks into production, users report the system misses a key statute roughly one time in six on multi-hop questions (questions requiring information from more than one source). The faithfulness dashboard still reads 0.91, unchanged — because faithfulness only measures whether the generated answer is grounded in whatever was retrieved. Checking context recall reveals the real problem: it had dropped to 0.62. The retriever was missing the second statute on multi-hop questions; the generator was answering coherently and faithfully from the partial context it had, so faithfulness stayed high while the actual answers were incomplete. No generation-only metric would ever have surfaced this regression.

Precision@k, Recall@k, and when you need labeled data

When you have labeled "gold" documents per query (a known-correct answer set), classic information-retrieval metrics apply directly: Precision@k and Recall@k at a specific cutoff, plus ranking-aware metrics like MRR (Mean Reciprocal Rank) and NDCG, which matter because a correct chunk buried at position 8 of 10 retrieved results is often functionally invisible to the model. When you don't have labeled gold documents, LLM-judge versions of context precision and answer relevancy can substitute — though context recall specifically still needs some form of reference answer or gold chunk set to compute reliably.

Check your understanding

1. Why can a RAG system show high faithfulness while still giving incomplete answers?
This is exactly the legal-research example — faithfulness measures generation quality given whatever context was retrieved, so a retriever quietly missing information can hide behind a perfectly consistent faithfulness score.
2. What does context recall specifically measure?
Context recall is a retrieval-stage metric checking completeness of what was retrieved against what was actually needed — distinct from faithfulness, which only checks the generator's use of whatever was retrieved.
3. Why does ranking matter (MRR, NDCG) beyond just whether the correct chunk was retrieved at all?
Presence alone isn't sufficient — where a relevant chunk lands in the returned ranking affects whether it meaningfully influences the model's answer, which is exactly what ranking-aware metrics like MRR and NDCG are built to capture.
