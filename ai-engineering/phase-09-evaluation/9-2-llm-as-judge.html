9.2 LLM-as-judge

Using an LLM to grade an LLM — genuinely useful, and genuinely easy to get wrong if it isn't calibrated first.

TL;DR
LLM-as-a-judge uses a model to score, classify, or compare outputs against a reference or rubric — the practical alternative when a task is too open-ended for deterministic checks (9.1) but still needs to be evaluated at scale, faster and cheaper than pure human review. The step teams skip, and shouldn't: calibrate the judge against real human verdicts before trusting its scores — grade a sample of cases by hand, compare the judge's verdicts against those, and only rely on the automated judge once it agrees with human judgment closely enough on a held-out sample.

Try it: would you trust this judge?

A judge prompt was calibrated against 5 human-graded cases. Guess whether the judge agreed with the human verdict before revealing the answer.

What a judge prompt actually looks like

Compare the generated RESPONSE to the REFERENCE answer.
Evaluate whether the generated response correctly conveys the
same meaning, even if the wording differs.

REFERENCE: {reference_answer}
RESPONSE: {generated_response}

Return one of: "Correct" or "Incorrect"

This is an offline evaluation — the judge compares against a known-good reference, most useful during active development (iterating on system design) and for regression testing after a model or prompt change. It's a direct alternative to older deterministic text-overlap metrics like ROUGE, which only measure word/phrase overlap and can score a correct paraphrase as wrong simply because the wording differs from the reference.

Judges for things that don't have a single "correct" reference

Not every eval has a golden reference answer to compare against — production traffic usually doesn't come with labeled expected outputs at all. For these reference-free cases, a judge evaluates a quality dimension directly against a rubric: is this response faithful to the retrieved context (6.4)? Did the agent complete its assigned task? Did it use the right tool with the right arguments? These reference-free judge metrics are what make ongoing production monitoring possible, not just pre-deployment testing.

Why calibration is the step that can't be skipped

An uncalibrated judge is a plausible-sounding number with unknown reliability — it might systematically favor longer answers, or miss subtle factual errors a domain expert would catch immediately. The recommended process: grade a set of real cases by hand yourself (or with a domain expert), run the judge prompt against the same cases, and only trust the judge's scores at production scale once its verdicts closely track the human-graded verdicts on that held-out sample. A judge that hasn't been checked against real human judgment is a plausible number, not a validated metric.

Check your understanding

1. Why is LLM-as-a-judge often preferred over strict text-overlap metrics like ROUGE?
ROUGE-style metrics measure surface word/phrase overlap, which penalizes a correct answer that happens to use different wording than the reference — a judge can evaluate meaning rather than surface form.
2. Why do many production evaluations need reference-free judge metrics rather than reference-based ones?
Reference-based judging works well during development against a known-good answer set, but live production requests generally arrive with no golden answer attached — reference-free rubric-based judging is what makes ongoing monitoring possible.
3. Why must a judge be calibrated against human verdicts before being trusted at scale?
Without checking judge verdicts against real human grading on a held-out sample, there's no evidence the judge's scores actually track quality the way a person would judge it — calibration is what turns a plausible number into a validated metric.
